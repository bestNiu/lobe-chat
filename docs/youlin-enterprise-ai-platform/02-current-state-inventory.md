## 0. 这份手册解决什么问题

本手册用于在二次开发前回答六个必须有证据的问题：

1. 企业现在实际上如何运作，而不是制度文件声称如何运作；
2. 员工、部门、在职状态分别以新人新事、企业微信还是 SSO 中哪个系统为权威源；
3. 哪个系统、角色或记录产生最终业务事实；
4. 数据从哪里来、经过什么处理、由谁负责、最终写回哪里；
5. 哪些步骤适合 AI 辅助，哪些必须由规则或授权人员完成；
6. 平台 MVP 和后续业务场景分别如何形成可验证闭环。

完成盘点后的必要输出：

- 企业系统地图；
- 业务流程与审批生命周期地图；
- 数据源、主数据、指标和知识资产清单；
- 组织、身份、角色和权限矩阵；
- 集成接口与网络依赖清单；
- 合规、隐私、安全和验证范围；
- 用户工作样本与业务基线；
- SSO、企业微信、账号关联、组织同步和离职回收现状；
- Web、Desktop、私有部署和终端管理现状；
- Skill、Tool、Workflow、知识资产及其 Owner/发布流程；
- 平台 MVP 与后续业务场景优先级建议；
- 已知事实、冲突、假设、风险和待决策事项。

这不是一次“需求收集会”。它是对企业业务事实和系统事实的核验。

## 1. 使用规则

### 1.1 证据等级

每项结论必须标记证据类型：

| 标记 | 证据类型 | 示例 | 可以支持什么结论 |
| --- | --- | --- | --- |
| `SYS` | 系统核验 | 数据库、接口返回、权限实测、日志 | 当前系统确实如何运行 |
| `DOC` | 受控文件 | 生效 SOP、制度、合同、验证报告 | 企业要求如何运行 |
| `OBS` | 现场观察 | 跟随用户完成一笔真实业务 | 用户实际上如何工作 |
| `REP` | 访谈陈述 | 用户或负责人描述 | 需要进一步验证的事实线索 |
| `MET` | 量化数据 | 工单、时长、错误、审计发现 | 规模、频率和价值基线 |
| `INF` | 分析推断 | 架构或产品团队判断 | 设计假设，不能冒充事实 |

推荐的置信度：

- **高**：至少两个独立证据，其中一个是 `SYS/DOC/OBS/MET`；
- **中**：单一强证据，或多个一致的访谈陈述；
- **低**：只有单一访谈或分析推断。

### 1.2 事实、制度和心智必须分开

一个流程常有三种不同版本：

- 制度要求的流程；
- 系统允许的流程；
- 用户实际采用的流程。

三者不一致不是调研失败，而是最有价值的发现。禁止用其中一个自动覆盖另外两个。

### 1.3 盘点状态

所有清单使用统一状态：

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚未联系负责人 |
| 收集中 | 已有材料，但证据不完整 |
| 待核验 | 已有结论，需要系统或样本验证 |
| 有冲突 | 不同证据互相矛盾 |
| 已确认 | 负责人和证据均确认 |
| 不适用 | 经说明后排除 |

### 1.4 不允许的捷径

- 不根据系统名称推断业务概念；
- 不根据界面缺失推断业务不存在；
- 不把数据库状态名直接当成用户状态；
- 不把“有接口”理解为“允许集成”；
- 不把“有审计字段”理解为“符合审计要求”；
- 不把 AI 生成结果理解为已经批准的业务事实；
- 不用管理者访谈代替一线工作观察；
- 不在没有基线时承诺节省比例。

### 4.3 系统边界核验问题

对每个系统必须问：

1. 它保存的是权威事实，还是权威事实的副本？
2. 谁能创建、修改、批准、删除和导出？
3. 删除是软删除、硬删除还是归档？
4. 哪个动作会让业务生命周期真正结束？
5. 审计能否重建创建、修改、批准、导出和删除过程？

### 9.7 Agent 上下文负向样本

至少验证：

- Project-B Agent 不加载 Project-A 私有记忆；
- PM 能看项目共享上下文但不能看成员个人项目记忆；
- 管理层只能在批准范围下钻项目敏感分区；
- 服务账号不能扩大用户权限；
- 多人共享会话不泄漏仅发起人可见内容；
- 使用个人记忆的产出物默认不能发布到项目；

- 搜索计数、自动补全和图关系不泄漏无权项目。

6. 每个状态意味着谁必须做什么？

11. 哪些错误最严重，哪些只是麻烦？

- 测量首批周期和工时基线。

退出标准：每个候选场景能说清触发、终态、责任人和证据。

### 第 3 周：接口、合规与技术验证

- 验证接口、认证、网络和数据样例；
- 完成数据分类与预期用途初判；

- 验证 RAGFlow 受控检索与引用；
- 验证 Dify 工作流调用与版本回传；

退出标准：至少一条只读链和一条受控动作链跑通测试环境。

### 第 4 周：优先级、方案与立项

- 确认首期最小可行产品；
- 输出目标范围、非目标和验收标准；
- 建立风险、决策和依赖清单；
- 形成 90 天实施计划和资源需求。

退出标准：业务、技术、QA、安全和法务对首期边界共同签字确认。
