# MVP PRD：Study 启动文件接收与 TMF 智能质检闭环

> 状态：产品需求候选基线 1.0  
> 产品：Youlin Clinical AI Hub  
> 目标版本：MVP 0.1  
> 关联契约：[集成契约](./06-integration-contracts.md)  
> 说明：本 PRD 中的角色、流程和指标必须经过真实业务调研后冻结。

## 1. 产品摘要

首个 MVP 选择“Study 启动文件接收与 TMF 智能质检闭环”，而不是单纯知识问答。原因是该场景：

- 有明确输入：Study 启动文件；
- 有可衡量处理过程：上传、解析、分类、规则检查、复核；
- 有明确责任人和终态：通过、退回修改、关闭；
- 可串联 LobeHub、RAGFlow、Dify、Tool Gateway 和 BPM；
- 风险可控：AI 提建议，人完成最终复核；
- 可形成完整审计和业务价值指标。

闭环：

```text
创建 Study → 接收文件 → 安全扫描/解析 → 自动分类与 QC
→ TMF 专员复核 → 问题整改 → QA/授权人审批
→ 受控归档 → 证据和指标沉淀
```

## 2. 背景与问题

候选问题假设：

- 文件经邮件、IM、共享盘等多渠道到达，入口和状态分散；
- 人工识别文件类型、版本、命名和必填元数据耗时；
- 缺失、过期、重复或错误版本发现较晚；
- QC 依据分散在 SOP、Study 计划和客户规则中；
- 整改意见缺少结构化跟踪；
- 管理者难以确认“哪些已检查、谁确认、依据哪个版本规则”；
- AI 试验结果与正式审批、证据归档脱节。

上述内容是待验证假设。立项前应采集至少 2～4 周真实基线数据。

## 3. 产品目标

### 3.1 业务目标

1. 建立 Study 文件统一接收、处理和状态入口；
2. 自动完成初步分类、元数据抽取和规则预检；
3. 将 AI 发现转化为可分派、可整改、可关闭的问题；
4. 将人工复核和 BPM 审批接入同一证据链；
5. 保持源文件、规则、模型、结果和人工决定可追溯；
6. 证明在不降低质量的前提下缩短文件 QC 周期。

### 3.2 非目标

MVP 不包含：

- 替代正式 eTMF 的全部能力；
- 自动把 AI 结果作为最终合规结论；
- 自动删除、覆盖或签署受控文件；
- 全量 CTMS/EDC/QMS 集成；
- 受试者级 PHI 数据处理；
- 所有国家、客户和 TMF Reference Model 规则；
- 大规模历史档案迁移。

## 4. 用户与角色

| 角色 | 目标 | MVP 权限 |
| --- | --- | --- |
| Study PM | 掌握启动文件准备和风险 | 查看 Study 总览、分派问题、查看进度 |
| TMF 专员 | 高效完成文件分类和 QC | 上传、复核 AI 建议、创建/关闭 Finding |
| 文件提交者 | 提交并修正材料 | 上传、查看本人相关退回项、提交新版本 |
| QA/授权审批人 | 确认流程和证据完整 | 审批或退回 QC 包 |
| 平台管理员 | 管理规则、模型和集成 | 配置，不参与业务终态 |
| Auditor/Viewer | 查阅证据 | 只读查看已授权 Study 的记录 |

AI Agent 不是法律或流程责任人，不作为审批人。

## 5. 核心对象

| 对象 | 说明 |
| --- | --- |
| Study | 项目与权限隔离边界 |
| Submission Batch | 一次提交的一组文件 |
| Document | 文件的稳定业务身份 |
| Document Version | 不可变文件版本及 Hash |
| QC Profile | 版本化的规则集合 |
| QC Run | 对确定文件版本和规则版本的检查运行 |
| Finding | 可跟踪的问题项 |
| Review Decision | 人工接受、修改或拒绝 AI 建议的决定 |
| Approval Instance | BPM 中的正式审批实例 |
| Evidence Package | 文件、规则、结果、决定和审批的证据包 |

### 5.1 关键不变量

- QC Run 必须绑定不可变 `documentVersionId`；
- 新文件版本不得覆盖旧版本及其历史结论；
- Finding 关闭必须记录责任人、时间、说明和证据；
- Approval 必须引用确定版本的 QC 报告；
- 已批准证据包不可静默修改，只能创建新版本；
- AI 输出必须标记模型、Prompt、Workflow、知识和规则版本。

## 6. 端到端用户旅程

### 6.1 创建 Study 工作空间

1. 管理员或 PM 创建 Project/Study；
2. 选择成员和临床角色；
3. 绑定 Study Knowledge Base、QC Profile 和审批流程；
4. 系统创建默认文件目录与 TMF QC Agent；
5. 记录配置版本和操作者。

### 6.2 接收文件

1. 提交者进入 Study 文件入口；
2. 选择文件或批量拖拽上传；
3. 系统执行扩展名、MIME、大小、Hash 和恶意文件检查；
4. 用户填写或确认文件类型、国家、Site、版本等元数据；
5. 系统生成 Document Version，原件写入 S3；
6. 上传成功后进入“待解析”。

### 6.3 解析与预检

1. Youlin 发布 `document.ingestion.requested`；
2. RAGFlow 解析文件并生成可引用内容；
3. 解析失败进入人工处理队列，不丢失原件；
4. Dify Workflow 执行分类、字段抽取和 QC；
5. Tool Gateway 按需读取 Study 配置和受控规则；
6. 输出结构化 Findings 和引用证据；
7. 页面展示“AI 建议，待人工复核”。

### 6.4 人工复核

TMF 专员逐项处理：

- 接受 Finding；
- 标记误报并填写原因；
- 修改严重级别或分类；
- 新增人工 Finding；
- 将问题分派给提交者；
- 确认无需整改。

所有修改形成审计记录，不覆盖原始 AI 输出。

### 6.5 整改与重检

1. 提交者收到任务；
2. 查看 Finding、规则和原文引用；
3. 上传新版本或填写说明；
4. 系统自动关联旧版本和 Finding；
5. 对新版本重新运行 QC；
6. 专员确认 Finding 已解决或继续退回。

### 6.6 审批与归档

1. 所有阻断 Finding 关闭后生成 QC 报告；
2. 报告包含文件版本、规则、AI 输出、人工决定和未关闭风险；
3. 发起 BPM 审批；
4. QA/授权人批准、拒绝或要求修改；
5. 批准后生成 Evidence Package 和不可变 Hash；
6. 状态更新为“已批准/可归档”；
7. 如对接 eTMF，只通过受控 Tool 创建草稿或提交任务，不自动代签。

## 7. 状态模型

### 7.1 Document Version

```text
uploaded → scanning → parsing → ready_for_qc → qc_running
→ review_required → remediation → approval_pending → approved → archived
```

异常状态：

```text
scan_rejected / parsing_failed / qc_failed / approval_rejected / withdrawn
```

### 7.2 Finding

```text
proposed_by_ai → accepted / dismissed / modified
accepted → assigned → remediation_submitted → verified → closed
                                            ↘ reopened
```

### 7.3 Submission Batch

```text
draft → submitted → processing → review → remediation
→ approval_pending → approved → archived
```

状态转换由服务端规则控制，前端不能直接写任意状态。

## 8. 功能需求

### FR-01 Study 范围与成员

- 支持创建 Study、添加成员和设置角色；
- 所有查询强制按 Workspace + Study 过滤；
- 无 Study 权限用户不能通过 URL、搜索或 Agent 间接访问资源；
- 移除成员后立即失去在线访问权。

### FR-02 文件上传与版本

- 支持 PDF、DOCX、XLSX，具体白名单可配置；
- 支持批量上传、进度、失败重试；
- 计算并保存 SHA-256；
- 同一 Hash 提示重复，不静默覆盖；
- 新版本建立版本链；
- 保存上传者、来源、时间、文件名和元数据。

### FR-03 文档解析

- 异步调用 RAGFlow；
- 展示排队、运行、成功、失败；
- 失败支持重试和人工标记“不可解析”；
- 解析内容引用回原始页码；
- 撤回文件立即停止在线检索。

### FR-04 自动分类和元数据建议

- 输出建议 TMF 分类、文档类型、版本、日期、Site/国家；
- 每个建议显示置信度和证据；
- 用户可接受、修改或拒绝；
- 用户决定作为反馈记录，不自动训练生产模型。

### FR-05 QC 规则检查

MVP 规则至少覆盖：

- 文件命名和允许格式；
- 必填元数据；
- 文档日期、版本和状态一致性；
- 重复文件；
- 过期/失效版本提示；
- 指定文本字段存在性；
- Study 配置的必需文档清单。

规则分为确定性规则和 AI 规则，界面必须明确区分。

### FR-06 Finding 管理

- Finding 包含类型、严重级别、描述、依据、引用、状态、责任人；
- 支持筛选、排序、批量分派；
- 支持评论和整改证据；
- 阻断 Finding 未关闭时禁止进入批准；
- 误报关闭必须填写原因。

### FR-07 Human-in-the-Loop

- AI Finding 默认不直接成为正式结论；
- 人工决定保留 AI 原始值和修改后值；
- 高风险 Finding 需要第二人复核可配置；
- 审批前展示未关闭风险和模型不确定性。

### FR-08 BPM 审批

- 通过 Adapter 发起确定版本流程；
- 展示当前节点、处理人和历史；
- 支持批准、拒绝、要求修改；
- 审批权限和电子签名由 BPM 执行；
- 回调失败可补偿查询；
- BPM 终态与 Youlin 投影不一致时告警并禁止归档。

### FR-09 证据包

证据包至少包含：

- 文件及版本 Hash；
- QC Profile 和规则版本；
- RAGFlow 解析版本；
- Dify Workflow、模型和 Prompt 版本；
- AI 原始 Findings；
- 人工复核轨迹；
- 整改材料；
- BPM 审批 ID 和签名引用；
- 生成时间和完整性 Hash。

### FR-10 Dashboard

按 Study 展示：

- 各状态文件数量；
- 待复核、待整改、待审批；
- Finding 严重度和逾期；
- 首次通过率；
- 平均处理周期；
- AI 建议接受/误报比例；
- 解析和集成失败。

## 9. 页面范围

MVP 页面：

1. Study 列表与详情；
2. Study 文件/提交批次列表；
3. 上传向导；
4. 文件详情与版本；
5. 解析和 QC 运行详情；
6. Finding 列表和详情；

## 11. 非功能需求

### 11.1 安全

- 浏览器不接触 RAGFlow/Dify/BPM 的服务密钥；
- 文件下载使用短期 URL；
- Workspace/Study 隔离有自动化测试；
- 敏感数据日志脱敏；
- 文件扫描和 SSRF 防护；
- Tool 调用按最小权限；
- 默认禁止 PHI 文件进入 MVP。

### 11.2 性能候选

- 列表 P95 ≤ 2 秒；
- 单文件上传后 2 秒内显示任务状态；
- 普通 PDF 95% 在 15 分钟内完成解析和初检；
- 状态事件在 10 秒内反映到 UI；
- 支持的文件大小和并发通过容量测试冻结。

### 11.3 可用性与恢复

- 外部平台短时不可用时保留任务并可重试；
- 不因重复消息产生重复版本、Finding 或审批；
- 所有异步任务可查询和人工重放；
- 明确 RTO/RPO，MVP 建议先按内部非关键系统等级评估。

### 11.4 可访问性与国际化

- 首期支持简体中文，关键临床字段预留英文；
- 错误不能只用颜色表达；
- 操作按钮使用确定性文案；
- AI 建议、人工决定和审批终态视觉上明确区分。

## 12. 成功指标

上线前采集基线，上线后按同口径比较。

### 12.1 业务指标

| 指标 | 目标候选 |
| --- | ---: |
| 单文件人工初检时间 | 相对基线降低 ≥ 30% |
| 从提交到首次反馈周期 | 相对基线降低 ≥ 25% |
| 必填字段/命名规则漏检 | 不高于人工基线 |
| 阻断 Finding 未关闭却批准 | 0 |
| 证据包完整率 | 100% |
| 用户任务完成率 | ≥ 90% |

### 12.2 AI/RAG 指标

| 指标 | 目标候选 |
| --- | ---: |
| 文档类型分类 Macro-F1 | ≥ 0.90 |
| 关键元数据准确率 | ≥ 95% |
| Finding Precision | ≥ 85% |
| 高严重度 Finding Recall | ≥ 95% |
| 引用可定位率 | ≥ 98% |
| 无依据结论率 | ≤ 2% |

目标必须由脱敏金标准数据集验证，不能只用演示样本。

### 12.3 系统指标

- 跨 Study 权限泄漏：0；
- 重复回调导致重复业务记录：0；
- 外部任务状态可恢复率：100%；
- 关键操作审计覆盖率：100%；
- MVP 期间严重安全事件：0。

## 13. 验收标准

### AC-01 权限隔离

**Given** 用户只属于 Study A  
**When** 通过页面、API、搜索、Agent、Tool 尝试访问 Study B  
**Then** 全部拒绝，且记录授权失败审计，不泄漏资源名称和元数据。

### AC-02 文件不可变版本

**Given** 文件 V1 已完成 QC  
**When** 上传修订文件  
**Then** 创建 V2，V1、原 QC 和证据仍可追溯，V2 重新检查。

### AC-03 解析失败恢复

**Given** RAGFlow 暂时不可用  
**When** 上传文件  
**Then** 原文件保存成功、任务标记失败/待重试，恢复后可幂等重放。

### AC-04 引用证据

**Given** AI 创建 Finding  
**Then** Finding 显示规则版本以及可定位到文件版本和页码的引用；无依据时明确标记而不是伪造引用。

### AC-05 人工复核

**Given** AI 建议错误分类  
**When** TMF 专员修改  
**Then** 系统同时保留原建议、修改值、操作者、原因和时间。

### AC-06 阻断控制

**Given** 存在未关闭的阻断 Finding  
**When** 用户尝试发起最终审批  
**Then** 服务端拒绝并返回具体阻断原因。

### AC-07 BPM 终态

**Given** QC 包已提交 BPM  
**When** QA 批准并完成签名  
**Then** Youlin 核验 BPM 终态后生成批准证据包；仅有本地回调不能伪造批准。

### AC-08 幂等

**Given** 上传、Workflow 或回调请求重复到达  
**Then** 不创建重复 Document Version、QC Run、Finding 或 Approval。

### AC-09 审计

**Given** 任一文件完成闭环  
**Then** Auditor 可还原文件、规则、模型、AI 输出、人工决定、审批和归档的完整时间线。

### AC-10 降级

**Given** Dify 不可用  
**Then** 用户可以继续保存文件并进入人工队列，系统不误报为 QC 通过。

## 14. 测试策略

- 单元测试：状态机、权限、规则、幂等；
- 契约测试：RAGFlow、Dify、BPM、Tool Gateway；
- 集成测试：上传到证据包全流程；
- 安全测试：越权、IDOR、SSRF、恶意文件、Webhook 重放；
- AI 评测：固定金标准、版本对比和回归阈值；
- 性能测试：并发上传、解析队列、检索和回调；
- UAT：PM、TMF、QA 使用真实脱敏工作样本；
- 验证：根据 GxP 范围形成 URS/风险/测试证据。

## 15. 发布门槛

进入 Pilot 前必须满足：

- P0 功能和 AC-01～AC-10 全部通过；
- 无未关闭 Critical/High 安全问题；
- 权限隔离自动化测试通过；
- 金标准评测达到冻结阈值；
- 回滚、备份、外部平台故障演练完成；
- QA、业务 Owner、信息安全和技术负责人批准；
- 用户培训、支持和事件响应流程就绪。

## 16. Pilot 方案

- 选择 1 个低风险、资料量适中的 Study；
- 5～15 名用户；
- 2～4 种文档类型；
- 使用脱敏或明确授权数据；
- 并行保留原流程，不立即替代正式 eTMF；
- 运行 4～6 周；
- 每周复盘误报、漏报、耗时、权限和用户反馈；
- 达标后再扩展 Study、规则和系统写回。

## 17. 开放问题

1. 首个 Pilot Study 和文档类型；
2. 企业采用的 TMF Reference Model/客户规则；
3. 正式 eTMF 是否提供 API；
4. BPM 产品及电子签名能力；
5. 是否属于 GxP 验证范围；
6. 文件数据等级、地域和保留期限；
7. 金标准由谁标注和批准；
8. Finding 严重度和关闭责任矩阵；
9. 目标基线数据和可接受质量阈值。
