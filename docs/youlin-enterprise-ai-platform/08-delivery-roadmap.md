# Youlin Clinical AI Hub 交付路线：人力、排期、预算、采购与风险

> 状态：ROM 规划基线 1.0  
> 规划周期：MVP 约 24 周 + 4～6 周 Pilot  
> 目标闭环：[Study 启动文件接收与 TMF 智能质检](./07-mvp-product-spec.md)  
> 估算精度：立项早期 Rough Order of Magnitude，误差可能为 ±30%～50%

## 1. 规划假设

本路线基于以下假设：

- 基于现有 LobeHub `v2.2.17` 企业分支二开；
- 首期只交付一个完整闭环，不同时改造全部 CRO 系统；
- 采用 1 个 Pilot Study、5～15 名用户、2～4 类文件；
- 复用企业现有 IdP、S3/对象存储、PostgreSQL 和 Kubernetes/容器平台中的可用部分；
- RAGFlow、Dify、BPM 部署版本和许可尚待确认；
- MVP 默认不处理受试者级 PHI；
- 正式审批由企业 BPM/OA 完成；
- eTMF 首期可只读或人工归档，不承诺自动写回；
- 是否纳入 GxP 计算机化系统验证由 QA 风险评估决定。

任一假设变化都可能影响范围、预算和排期。

## 2. 交付目标

24 周内形成：

1. 可持续同步 LobeHub 上游的企业代码基线；
2. 企业 SSO、Workspace/Study 和角色权限；
3. 文件上传、不可变版本和资源治理；
4. RAGFlow 文档解析与引用；
5. Dify TMF QC Workflow；
6. Finding 人工复核和整改；
7. BPM 审批和证据包；
8. Tool Gateway、审计、Tracing 和配额；
9. 金标准 AI/RAG 评测与安全测试；
10. 一个真实 Study 的受控 Pilot。

## 3. 阶段路线

```text
W1-2   立项、许可、现状核验
W3-5   架构基线、环境、CI/CD、身份
W6-9   Study/权限、文件与版本
W8-12  RAGFlow、检索、引用与评测集
W10-14 Dify QC、Finding、人工复核
W13-17 BPM、Tool Gateway、证据包
W16-20 E2E、安全、性能、验证准备
W21-24 UAT、发布准备、Pilot 上线
W25-30 Pilot 运行与评估
```

部分工作并行，但权限、文件版本和审计基础必须先于业务自动化。

## 4. 详细阶段与门禁

### 阶段 0：立项与尽调，W1～W2

工作：

- 确认 LobeHub、Dify、RAGFlow 及其他依赖许可；
- 确认 Pilot Study、业务 Owner、QA 和用户；
- 按现状盘点手册采集流程、样本和基线；
- 确认数据等级、驻留、跨境和 GxP 范围；
- 核验 IdP、BPM、eTMF、CTMS 接口；
- 冻结 MVP In/Out Scope；
- 建立风险、决策和需求追踪台账。

退出门槛：

- 商业/法务允许继续；
- Pilot 业务和数据 Owner 明确；
- 有可使用的脱敏样本；
- 架构关键问题有决策责任人；
- MVP 范围获业务、技术、QA 批准。

### 阶段 1：工程与平台基线，W3～W5

工作：

- 开发、测试、UAT 环境；
- CI/CD、制品、SBOM、依赖和镜像扫描；
- Secret 管理、日志、Tracing、告警；
- SSO/OIDC 和基础用户同步；
- Model Gateway 最小接入；
- 上游同步和分支保护；
- ADR、编码和发布规范。

退出门槛：

- 环境可重复部署；
- 企业用户可登录测试环境；
- Secret 不进入代码和镜像；
- 基础监控、备份和恢复演练可执行；
- CI 质量门禁生效。

### 阶段 2：Study、权限与文件，W6～W9

工作：

- Workspace/Project/Study 映射；
- 临床角色和 Study 成员；
- RBAC + Study ABAC + Resource ACL；
- 文件上传、安全扫描、Hash 和不可变版本；
- Submission Batch 和文档元数据；
- 审计事件；
- 跨 Study 权限测试。

退出门槛：

- 文件可按 Study 接收和版本化；
- 权限测试无跨范围泄漏；
- 新版本不覆盖历史；
- 关键操作可追溯。

### 阶段 3：知识与 RAGFlow，W8～W12

工作：

- Knowledge Provider 和 RAGFlow Adapter；
- 异步摄取、状态、失败重试；
- 文档撤回和索引失效；
- Hybrid Search、Rerank 和元数据过滤；
- 页码、版本和引用快照；
- 金标准文档和检索评测集；
- RAG 质量、延迟和成本基线。

退出门槛：

- 支持的样本解析稳定；
- 检索不突破 Study/文档权限；
- 引用可定位到确定文件版本和页码；
- 达到冻结的 Recall@K/引用阈值。

### 阶段 4：Dify QC 与人工复核，W10～W14

工作：

- Workflow Provider 和 Dify Adapter；
- Workflow 注册、版本和 Schema；
- 文档分类、元数据建议和 QC；
- Finding 状态机；
- 人工接受、修改、误报和新增；
- 整改任务和新版本重检；
- AI 评测和版本回归。

退出门槛：

- Workflow 可固定版本运行；
- 输出通过 Schema 校验；
- AI 原始输出和人工修改同时保留；
- 阻断 Finding 能控制后续流程；
- 分类、元数据和 Finding 指标达到 Pilot 阈值。

### 阶段 5：BPM、Tool Gateway 与证据，W13～W17

工作：

- Approval Provider 和 BPM Adapter；
- 待办、审批历史和回调；
- Tool Registry、调用、审批和凭证代理；
- QC 报告和 Evidence Package；
- 完整性 Hash；
- eTMF/CTMS 只读 Tool 或受控草稿接口；
- 外部服务故障补偿。

退出门槛：

- 正式终态由 BPM 核验；
- 重复请求/回调不创建重复记录；
- 高风险 Tool 未批准不能执行；
- Auditor 可重建完整处理时间线。

### 阶段 6：系统验证与发布准备，W16～W20

工作：

- E2E、性能、容量、安全和灾备测试；
- Prompt Injection、SSRF、IDOR、Webhook 重放测试；
- 供应链和镜像漏洞处理；
- GxP 风险评估和验证文档；
- 运维 Runbook、支持和事件响应；
- 用户培训材料；
- 数据备份、恢复和回滚演练。

退出门槛：

- P0 缺陷清零；
- 无未接受的 Critical/High 安全风险；
- 恢复和回滚演练通过；
- QA/安全/运维完成发布评审。

### 阶段 7：UAT 与 Pilot 上线，W21～W24

工作：

- 业务 UAT；
- 金标准复验；
- Pilot 数据准备和用户授权；
- 生产/Pilot 环境发布；
- 发布后监控和支持；
- Go/No-Go 决策。

退出门槛：

- PRD 验收标准通过；
- 业务 Owner、QA、信息安全签署 Go；
- 培训和支持值班就绪；
- 原流程保留作为降级路径。

### 阶段 8：Pilot，W25～W30

工作：

- 运行 4～6 周；
- 每周复盘误报、漏报、周期、失败和用户反馈；
- 对比原流程基线；
- 修复和小范围规则调整；
- 形成扩大、调整或停止建议。

Pilot 结束门槛：

- 业务和 AI 指标达到约定阈值；
- 无重大权限、安全或合规事件；
- 用户愿意持续使用；
- TCO 和扩展成本可接受；
- 第二阶段范围得到批准。

## 5. 团队配置

### 5.1 核心团队

| 角色 | 建议 FTE | 主要职责 |
| --- | ---: | --- |
| Product Owner/业务产品 | 1.0 | 范围、流程、验收、价值指标 |
| Solution Architect/Tech Lead | 1.0 | 架构、上游同步、关键设计和评审 |
| 前端工程师 | 1.5～2.0 | Study、文件、Finding、审批和证据界面 |
| 后端工程师 | 2.0～3.0 | 领域服务、权限、状态机、Adapter、审计 |
| AI/RAG 工程师 | 1.0～2.0 | RAGFlow、Dify、评测、Prompt/规则 |
| QA/SDET | 1.0～1.5 | 自动化、契约、E2E、性能和回归 |
| DevOps/SRE | 0.5～1.0 | 环境、CI/CD、监控、备份和恢复 |
| Security/Privacy | 0.2～0.5 | 威胁建模、测试、数据和供应链安全 |
| CSV/QA 合规 | 0.3～0.8 | 风险评估、验证策略和证据 |
| UX/产品设计 | 0.3～0.5 | 核心流程和可用性 |
| TMF/Clinical SME | 0.5～1.0 | 规则、样本、金标准、UAT |

核心峰值约 **9～12 FTE**，总投入约 **50～75 人月**，取决于现有平台复用度、接口质量和验证深度。

### 5.2 不建议压缩的角色

- Clinical/TMF SME：没有领域 Owner 无法建立可靠规则和金标准；
- QA/SDET：AI 工作流和多系统异步集成不能只靠手工测试；
- Security/Privacy：文件、模型和 Tool 带来新的数据外泄面；
- CSV/QA：如系统进入受监管范围，不能上线前临时补文档。

## 7. 预算估算

### 7.1 一次性 MVP 预算（人民币，不含税）

| 类别 | ROM 区间 | 说明 |
| --- | ---: | --- |
| 内部/外包研发人力 | 180～360 万 | 50～75 人月，取决于综合人月成本 |
| 基础设施与环境 | 15～60 万 | Dev/Test/UAT/Pilot、存储、数据库、监控 |
| GPU/模型与 API | 10～50 万 | 数据量、私有模型和评测调用影响较大 |
| 商业软件许可 | 20～150 万 | LobeHub/Dify/BPM/安全产品需询价和法务确认 |
| 安全测试与供应链 | 10～40 万 | 渗透、代码/镜像扫描和整改 |
| QA/CSV/验证 | 15～80 万 | 是否受 GxP 管控影响显著 |
| 培训、上线和支持准备 | 5～20 万 | 培训、Runbook、上线值守 |
| 风险预备金 | 上述的 15%～20% | 供应商 API、迁移和合规不确定性 |

综合 MVP ROM：**约 290～800 万元**。如果已有成熟平台、内部团队和许可，可能接近区间下限；如需要私有 GPU、企业许可、正式 CSV 和多个业务系统写回，则可能超过上限。

此数字不能用于采购定价，应在 W1～W2 完成供应商报价和工作分解后形成批准预算。

### 7.2 年度运行成本

| 类别 | 年度 ROM |
| --- | ---: |
| 平台运维与值守 | 40～120 万 |
| 云资源/存储/备份 | 20～100 万 |
| 模型与 Embedding | 20～200 万 |
| 软件续费与支持 | 20～200 万 |
| 安全、审计和验证维护 | 15～80 万 |
| 持续研发（2～5 FTE） | 80～250 万 |

年度成本高度依赖用户量、文档量、模型策略和企业许可，应按“每 Study、每千页、每次 QC、每活跃用户”建立单位成本。

### 7.3 成本控制

- 所有模型调用记录 Token、成本、Study 和用途；
- 解析、Embedding 按文件 Hash 去重；
- 开发、评测和生产使用独立预算；
- 小模型执行分类/抽取，大模型处理复杂判断；
- 缓存确定性结果，不缓存越权上下文；
- 设置 Workspace/Study/User/Agent 配额和告警；
- Pilot 不预购超出验证需求的大规模 GPU。

- 许可是否允许企业二开、内部部署和品牌修改；

- API 版本、限流、幂等、Webhook 和 SDK；
- 高可用、备份、恢复、升级和漏洞响应；
- 数据导出和退出机制，防止供应商锁定；
- SLA、支持窗口和严重事件通知；
- 分包商清单、DPA、保密和安全证明；
- 价格单位及增长曲线。

### 8.3 合同必须覆盖

- 数据所有权和允许用途；
- 数据驻留、跨境和删除证明；

- 版本停服和兼容公告期；
- 漏洞修复 SLA；
- 审计权和监管协助；
- 合同终止后的数据导出与销毁；
- 生产支持、升级和回滚责任。

## 11. 决策与变更控制

以下变更必须进入变更委员会评估，不作为普通需求直接插入 Sprint：

- 引入 PHI/受试者数据；
- 自动写回 CTMS/eTMF/EDC；
- 将 AI 输出作为正式终态；
- 增加国家、法人或数据区域；
- 更换模型、RAG 或 Workflow 生产版本；
- 修改权限模型、审计留存或电子签名；
- 增加新的 Pilot Study 或文档类型；
- 延后安全、测试或验证活动来追赶日期。

变更评估至少包含范围、风险、数据、验证、预算、排期和回滚影响。

## 12. 项目度量

每周：

- 范围燃尽、关键路径、阻塞和决策等待时间；
- 自动化测试、缺陷、漏洞和技术债；
- Adapter 成功率、任务失败和恢复；
- AI/RAG 评测趋势；
- 云和模型成本。

Pilot 每周：

- 文件量、完成周期、人工耗时；
- Finding 接受、修改、误报和漏报；
- 用户活跃和任务完成；
- 权限、审计、安全和合规事件；
- 相对原流程的实际收益。

禁止用聊天次数、Token 总量或 Agent 数量代替业务价值。

## 13. Go/No-Go 条件

### Go

- 所有 PRD P0 验收通过；
- 权限、安全和恢复测试通过；
- AI/RAG 达到 Pilot 阈值；
- 许可、DPA、数据和运维条件完成；
- QA、业务、安全和技术共同批准；
- 原流程和回滚路径可用。

### No-Go

任一情况应暂停：

- 商业许可或数据使用权不明确；
- 跨 Study 数据泄漏；
- 高风险 Finding Recall 未达到门槛；
- 无法还原审批或证据链；
- BPM 终态不可核验；
- Critical/High 安全风险未处理或未正式接受；
- 无业务/QA Owner 承担 Pilot 决策。
