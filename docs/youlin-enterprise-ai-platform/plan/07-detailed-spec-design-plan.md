## 4. 逐项认领与 DoR

每项候选 A 仅是责任角色，真实 A 必须唯一。技术、QA、安全、领域 Owner 作为 Reviewer 不自动组成多个 A。

开始编码前必须有：

1. approved 的单项版本与审批记录；或明确获批准、可独立验证的子切片。
2. 逐项用户故事/非目标、FR/AC/VT 映射和依赖提供时间。
3. 逻辑模型到实际仓库表/迁移的映射；唯一键、租户复合约束、并发与删除策略。
4. 精确 OpenAPI/JSON Schema/tRPC 输入校验及事件 Schema，含错误、授权、幂等、限流。
5. UI 原型/状态或写明不适用理由；同一操作的 Web/Desktop/API 行为一致。
6. 正向/越权/超时/恢复用例和合成夹具；测试环境与预期证据。
7. Feature Flag、回滚/前向修复、可观测、Runbook、保留与退出策略。
8. 角色人日估算、实际可用容量、审批证据和所有关键 TBD 已关闭。

文档/ADR 类任务：API/Schema/UI 可以不适用，但必须有决策输入、选项、证据、批准角色与后续阻断条件。不能因没有代码就免除验收。

## 5. 状态与证据合同

采用 [Spec 工作区](./specs/README.md) 的双轴状态；旧 reviewed/in_verification 口径分别对应设计评审记录/交付验证，不自动推导 approved/verified。

索引中的 `owner=null`、`approvalEvidence=[]`、`schemaRefs=[]` 表示真实未就绪，不是默认批准。后续状态变更必须同步文档与 catalog；用版本化受控证据引用，不能把生产原文/Secret 放入 Git。

关键 TBD 记录：问题、关联 D 编号、影响对象、候选选项、需要的实证、责任角色、截止周、默认拒绝/降级、批准版本。临时测量值不得伪装成 SLA。

## 8. 批次 3 的安全前置与交付边界

- **W11 资源 API**：M06-009 配额预留/释放、M06-012 MIME/格式/大小/扫描必须一起提供；不能等待 W14 运营页面/完整预览才实现上传安全。
- **扫描到发布**：扫描结果必须绑定确切对象版本/Hash，提交不可变载荷时核验相同内容，防隔离区上传凭证尚有效期间替换对象。
- **知识原子激活**：控制面发布指针绑定 generation；数据库/Provider 无跨库事务时不混读半成品。失败可保留的旧发布必须仍有效且获授权。
- **C1 记忆与产物**：个人记忆显式开关/来源控制，Promotion 只审脱敏草稿，生成文件不能丢失来源分类/ACL；完整多人输出随 M10 交付，早期默认私有。
- **应用融合**：W8 合同、W14 真实 CRM/OA 只读 Spike、W22 应用中心；Launch Code 单次原子消费且绑定模块/用户/目标，不替代 OIDC，不透传 Token，嵌入不兼容降级安全深链接。

## 9. 批次 4 的消费者与门禁

- **员工助手**：来源适用范围/时效与权限先于优先级；固定 Workflow 与真实 C1 链是前置，不以模型记忆补制度事实，冲突/无依据/超范围明确拒答或转人工。
- **质量和反馈**：W16 最小反馈落盘/人工分派与质量指标先行，W22 统一反馈平台消费同一记录，避免灯塔依赖尚未交付的运营中心；黄金集评测与线上抽样分开。
- **产品与质量**：M09-006 草稿契约给 M09-011 定义规则，候选 Gold/质量证据再反供产品激活；前置设计依赖图无环不表示运行发布可跳过质量门。
- **内部 API**：每页游标和缓存都绑定主体/Grant/策略/快照并重验当前授权；未知字段/过滤/排序拒绝，行列/脱敏在数据面执行。
- **源与新鲜度**：只摄取批准字段，禁止未批数据先落 Bronze；质量失败或源陈旧按批准合同阻断/明确标识，不能静默返回旧值。
- **范围**：一个低敏产品、一个内部只读 API 与独立 Client；目录发现、订阅、Gateway Scope 都不自动授数据读取权，外部生产消费者仍禁止。

## 10. 批次 5 的最终集成边界

- **多人会话**：Audience 变更使运行包与历史访问重新评估；无法证明旧回答对新成员安全时拒绝共享或新建安全会话，不能仅移除引用后展示旧正文。
- **项目与网络**：角色视图/汇总/节点/边/补全/计数都在授权事实集合内计算；管理职级不授全部项目或个人记忆读取权，MVP 不开放任意图查询。
- **全域失效**：M3/C0 先执行阻断，M10-010 补齐回执/历史链/网络投影；单人离项不物理删除其他合法成员共享索引，恢复先重放撤权/删除账本。
- **后台任务**：独立 Workload Grant、Owner、用途、期限和执行预算；每次调度/恢复/Tool/输出都复核，不借服务账号扩权。
- **工作中心**：Task 是源状态投影，通知受理/送达/已读分开；源超时显示未知/陈旧，不由平台伪造业务终态或盲目重试外部副作用。
- **自助与支持**：个人偏好不覆盖企业策略，Trace 不赋原文权限；工单仅收集显式授权片段，企业配置和 Flag 不回滚真实撤销事实。
- **运营验收**：W22 交付 UI/告警/手册与桌面推演，完整 AC-33、DR、容量与业务 UAT 在 M12；M13 仅 Pilot readiness，M14 才签实际运行结果。

`slicePlan` 只记录候选边界，未创建新的已批准任务或改变父 Spec 交付状态。切片验收记录必须带明确范围、排除项、真实/Mock 标记、制品/合同版本和批准证据；不能拿一个早期切片将整个父 Spec 标记 accepted。
