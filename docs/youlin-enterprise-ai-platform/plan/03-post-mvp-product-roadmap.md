# MVP 后完整产品开发路线

> 本文件把 `../12-full-product-capability-and-evolution-blueprint.md` 转换为可立项的后续开发阶段。
>
> 规划周期：24～36 个月滚动规划；每个 Stage 必须单独通过投资门。

## 1. Stage 投资门

进入任何后续 Stage 前必须同时满足：

```text
明确业务 Owner
+ 真实用户和基线
+ 数据可得且边界获批
+ 安全/隐私/QA 风险可接受
+ 技术 Spike 通过
+ 团队和运维能力可用
+ 量化验收与退出条件明确
```

不因模型演示效果、竞争压力或供应商宣传跳过投资门。

---

## Stage 1：企业采用与稳定化（3～4 个月）

### 目标

从 20～50 人 Pilot 扩大到 100～300 人，提升产品发现、内容运营、稳定性和支持成熟度。

### Epic 与 Spec 方向

| Epic | 功能要求 | 验收方向 |
| --- | --- | --- |
| S1-E01 企业推广 | 多部门启用、用户引导、常用入口、角色首页 | 新用户首次价值时间、部门覆盖 |
| S1-E02 搜索增强 | 跨资源/知识/项目/应用/数据搜索，个性化排序 | 搜索成功率、零结果率、无越权 |
| S1-E03 任务与待办 | 泛微待办/API 聚合、订阅、SLA 和升级 | 任务到达/完成、状态一致 |
| S1-E04 内容运营 | 内容缺口、过期提醒、Owner 工作台和发布日历 | 过期知识、反馈闭环 |
| S1-E05 Agent Marketplace | 分类、推荐、收藏、使用说明、版本和评分 | 采用率、成功率、下架能力 |
| S1-E06 项目上下文增强 | Project 首页、风险、行动、周报、组合摘要 | PM 使用率、跨项目隔离 |
| S1-E07 数据看板 | 首批经营/采用/质量指标和下钻 | 指标版本、数据质量和 RLS |
| S1-E08 平台生产化 | HA、容量、灾备、FinOps、服务台和发布节奏 | SLO、RPO/RTO、单位成本 |
| S1-E09 移动/企微入口 | 企业微信通知、工作助手入口和轻量任务 | 渠道一致性和安全 |
| S1-E10 治理运营 | 季度权限复核、Owner 复核、Flag 清理和技术债 | 到期授权、僵尸资产下降 |

### 退出门槛

- 覆盖 100～300 名员工和多个部门；
- 无重大身份/权限/数据事件；
- 首页、搜索、任务、员工助手和 Agent 的重复使用达到目标；
- 平台 SLO、支持 SLA、灾备和成本达到企业生产门槛；
- Stage 2 场景已有 Owner、基线和收益假设。

---

## Stage 2：项目经营与通用业务智能体（4～6 个月）

### 目标

把 Project 从权限/Context 骨架升级为项目经营与交付工作台，并建设低至中风险企业智能体。

### Epic 与 Spec 方向

| Epic | 功能要求 | 关键边界 |
| --- | --- | --- |
| S2-E01 Project 360 | 客户、合同、范围、成员、里程碑、风险、行动、交付 | 源系统事实可追溯 |
| S2-E02 PM Copilot | 风险摘要、周报、行动建议、会议纪要和 Context | 建议/草稿，不自动终态 |
| S2-E03 Portfolio | 项目组合、资源负载、收入成本、毛利和预测 | 指标语义和管理下钻 |
| S2-E04 报价辅助 | RFP 抽取、范围、角色工时、费用和版本差异 | 人工定价/审批终态 |
| S2-E05 智能报销 | 政策问答、票据抽取、完整性/合规校验、表单草稿 | 财务/OA 批准终态 |
| S2-E06 合同/法务导航 | 条款检索、差异和咨询路由 | 不形成法律终态意见 |
| S2-E07 数据产品扩展 | CRM、财务、项目和资源负载 Data Product | Gold/Contract/质量 |
| S2-E08 指标语义层 | 指标定义、版本、维度、RLS 和血缘 | AI 不自行发明 KPI |
| S2-E09 低风险写回 | 经审批后的 CRM/OA 草稿、任务和回执 | Tool Gateway、幂等、补偿 |
| S2-E10 Context Network | 项目/客户/合同/知识/指标关系和影响分析 | 节点/边/路径授权 |

### 退出门槛

- PM/项目团队完成真实经营和交付任务；
- 报价/报销至少一个场景达到可量化效率收益；
- 指标能下钻来源且权限正确；
- 所有写回有人工批准、幂等、回执和补偿；
- 临床场景数据和 QA 边界已为 Stage 3 准备。

---

## Stage 3：Clinical Copilot Suite（6～9 个月）

### 目标

以建议、草稿和影子模式建设临床业务 Copilot，不直接进入高风险自动终态。

### Epic 与 Spec 方向

| Epic | 功能要求 | 验收/边界 |
| --- | --- | --- |
| S3-E01 Study 模型 | Study/Country/Site/Role、与 Project 关系 | 权威源、有效期和 ABAC |
| S3-E02 Study Startup | 材料清单、缺口、责任人、时间和启动条件 | 不自动确认中心激活 |
| S3-E03 Protocol Assistant | 方案结构、入排、访视、术语和引用问答 | 版本/国家/角色范围 |
| S3-E04 CRA Assistant | 访视准备、检查清单、报告草稿和 Follow-up | CRA/PM 人工确认 |
| S3-E05 CRA Coach | 情景训练、知识测验、反馈和能力画像 | 不替代 LMS 正式培训记录 |
| S3-E06 TMF QC Shadow | 分类、命名、元数据、缺失和重复提示 | 影子运行，不自动归档终态 |
| S3-E07 Clinical Project Copilot | Study 风险、里程碑、行动和摘要 | 受控来源和角色化 Context |
| S3-E08 Clinical Knowledge | Protocol、计划、非敏感 SOP 的版本/引用 | Study/Country/Role 权限 |
| S3-E09 临床评测 | 专家标注、错误类别、风险阈值和人工监督 | 场景化评测集 |
| S3-E10 数据最小化 | 去标识化、字段白名单、用途和模型路由 | 禁止未批准 PHI/人遗 |

### 退出门槛

- 每个场景有独立 Intended Use、Owner 和风险等级；
- 建议/草稿模式达到业务质量门槛；
- Study/Site/Country ABAC 和引用权限通过；
- 专家确认不能接受的错误类型和自动化上限；
- 需要进入受控终态的场景形成 Stage 4 验证计划。

---

## Stage 4：受控与 GxP 场景（9～15 个月，按场景独立）

### 目标

对明确预期用途的受控场景实施验证、电子签名、变更和审计，不把整个工作台一次性视为 GxP 系统。

### Epic 与 Spec 方向

| Epic | 功能要求 |
| --- | --- |
| S4-E01 Intended Use/分类 | 明确每个模块是否创建、修改、判断或仅展示受控记录 |
| S4-E02 验证体系 | URS、FS/DS、风险评估、验证计划、追踪矩阵、IQ/OQ/PQ |
| S4-E03 电子签名 | 身份再认证、签名含义、记录绑定和不可抵赖 |
| S4-E04 受控审计 | Audit Trail、时间同步、导出、保留和审阅 |
| S4-E05 变更/偏差 | Change Control、验证影响、Deviation/CAPA 和回滚 |
| S4-E06 受控集成 | CTMS/eTMF/QMS/EDC 的验证接口、版本和回执 |
| S4-E07 高风险 Tool | 双人复核、职责分离、Expected Version、幂等和补偿 |
| S4-E08 模型变更 | 固定模型/Prompt/知识版本、性能监控、再验证和停用 |
| S4-E09 培训 | 角色培训、版本、到期和正式 LMS 记录 |
| S4-E10 记录保留 | ALCOA+、Legal Hold、归档、迁移和可读性 |

### 退出门槛

- 场景验证包批准；
- 所有用户、管理员和支持角色培训完成；
- 受控记录、签名和审计可还原；
- 重大偏差关闭，无未接受高风险；
- 生产变更进入正式 Change Control。

---

## Stage 5：外部产品与生态（6～12 个月，可与 Stage 3/4 并行）

### 目标

将成熟模块产品化为可独立部署/销售能力，并安全开放批准的数据和 API。

### Epic 与 Spec 方向

| Epic | 功能要求 | 关键门禁 |
| --- | --- | --- |
| S5-E01 产品包装 | Standalone/Embedded、品牌、域名、配置和安装 | 不依赖内部工作台运行 |
| S5-E02 客户身份 | 客户 OIDC/SAML、Client、组织和紧急账号 | 租户隔离测试 |
| S5-E03 部署模式 | SaaS/单租户私有化、K8s/容器、升级和备份 | 支持矩阵和 Runbook |
| S5-E04 Entitlement | 套餐、功能、配额、期限和服务端执行 | 不等同前端隐藏 |
| S5-E05 External Gateway | DMZ/WAF、OAuth2、mTLS、IP、配额和吊销 | 独立安全评审 |
| S5-E06 Developer Portal | OpenAPI、Sandbox、Client、订阅、用量和支持 | 合成/低敏测试数据 |
| S5-E07 外部 Data Product | 合同、目的、字段、地域、保留和删除 | 逐产品审批，跨境默认拒绝 |
| S5-E08 计量/商业 | 用户/API/存储/模型等计量和账单接口 | 准确性、争议和审计 |
| S5-E09 客户运维 | SLA、状态页、工单、告警、升级窗口和 EOL | 支持组织就绪 |
| S5-E10 迁移退出 | 配置/数据导出、删除证明、客户退出和版本迁移 | 可验证、可审计 |

### 退出门槛

- 目标客户、合同、数据边界和 SLA 明确；
- 租户、身份、数据、日志、缓存和备份隔离通过；
- 产品安装、升级、回滚、迁移和退出演练通过；
- 外部 API 无底层数据库/湖仓直连；
- 支持、定价、计量和版本生命周期可运营。

## 3. 版本节奏建议

- 双周 Sprint；
- 每月内部 Release Train；
- 每季度产品能力版本和投资复盘；
- 高风险/受控模块独立发布列车；
- 外部客户版本遵循长期支持和 EOL 策略；
- 每次上游 LobeHub 同步先进入集成分支并跑企业 E2E。

## 4. 规划更新规则

M14 Pilot 结束后，以实际指标替换当前假设：

- 真实采用和任务频率；
- 业务耗时、返工和质量基线；
- 数据源接口和质量；
- 模型、OSS、查询和支持单位成本；
- 身份、权限、Context 和集成复杂度；
- 内部团队产能和供应商交付能力。

后续 Stage 不应同时全量启动。优先选择 1～2 个有明确 Owner、数据和收益的 Epic，以季度为单位滚动投资。
