# 测试与验证策略：分层、双循环、加速与证据口径

> 本文是测试/验证的**单一策略来源**。环境细节见[本机测试环境](./10-local-test-environment.md)，部署与 UAT 步骤见[部署与本机 UAT 手册](./12-deployment-and-local-uat-runbook.md)，工具入口见 `scripts/youlin/docker/README.md` 与 `scripts/youlin/deployment/README.md`。
>
> 用户已明确放宽"测试与构建必须在 Docker 内"的默认：宿主原生允许用于开发内循环；Docker 仍是发布构建、真实服务与证据采集的载体。

## 0. 为什么需要这份策略：本轮真实逃逸的缺陷

| 缺陷 | 被哪一层抓到 | 教训 |
| --- | --- | --- |
| realm 缺 `basic` scope → 令牌无 `sub` → 登录全拒 | 只有**真实 IdP + 真实浏览器登录** | 14 项隔离协议测试全绿：夹具 realm 与实例 realm **配置漂移**，夹具不能代替实例 |
| `now()` 返回值不是 Date → 所有请求 `INVALID_INPUT` | 只有**部署后真实对话** | 12 项单测全绿：mock 掉的驱动行为无法覆盖真实类型解析 |
| 只读镜像上 prerender cache 写入失败 | 只有**只读镜像运行** | dev/宿主是可写文件系统，测不到 |
| phase 切换丢失网络别名 → `EAI_AGAIN postgres` | 只有**真实生命周期切换** | 单个 compose 文件的测试测不到跨 phase 复用 |
| OAuth state 5 分钟窗口 / 回调跳到 `0.0.0.0:3210` | 只有**真实浏览器** | 服务端单测看不到浏览器可达性 |

结论：**单测与静态检查负责逻辑分支，真实运行负责集成与配置漂移**。两层都不能省，但都可以更快——省的是等待，不是层次。

## 1. 分层：每层证明什么、跑在哪、能否作为验收证据

| 层 | 内容 | 载体 | 典型耗时 | 能证明 | 不能证明 |
| --- | --- | --- | --- | --- | --- |
| L0 静态 | 定向 lint、定向类型闭包 | 容器或宿主 | 秒～2 min | 风格、类型、明显错误 | 任何运行时行为 |
| L1 单元 | 纯函数/策略/映射/reducer（vitest、node:test） | 容器或宿主 | 秒级 | 分支与边界、负向路径 | 集成、配置、真实依赖 |
| L2 契约/仓储 | 真实 PostgreSQL 分片（当前 73+53=126 项） | 容器（双容器 RAM socket） | 1～2 min | SQL、事务、隔离、并发槽、fail-closed | 应用接线、真实 IdP |
| L3 组件集成 | 真实 SDK（如 Better Auth + 内存适配器） | 容器或宿主 | 秒级 | 钩子/中间件/allowlist 语义 | 真实数据库与网络 |
| **L4 服务集成（内循环）** | dev server + 真实 Keycloak/PG/Redis/网关 | dev 容器或宿主 | 秒级热更 | **配置漂移、真实协议、时钟/超时、URL/origin** | 生产 bundle、只读镜像、打包链 |
| **L5 镜像验收（外循环）** | 不可变 sha256 镜像 + 只读 FS + 限额 + 真实浏览器 | Docker 流水线 | 构建 2.5～10 min + 部署 2～4 min | 生产构建、只读文件系统、迁移链、部署生命周期 | 多用户并发、长期运行 |
| L6 产品 UAT | 双账号真实用户流程 + 证据归档 | 部署实例 | 每例 1～2 min | 用户可见结果 | 未覆盖场景仍需列出 |

**只有 L5/L6 可以作为验收证据。** L0～L4 通过只说明"逻辑与集成在开发形态下成立"。

## 2. 双循环（本轮最重要的策略变化）

```text
内循环（功能正确性）  改代码 → HMR 秒级 → 浏览器/接口验证 → 反复迭代      载体：dev 容器或宿主
外循环（可交付物）    构建不可变镜像 → upgrade/migrate/up → L5/L6 → 冻结证据   载体：Docker 流水线
```

规则：

1. 功能**先在内循环跑通**，外循环只做一次复核与证据冻结；不要每改一行就构建镜像。
2. **禁止**用内循环结果冒充镜像验收；也**禁止**因为内循环通过就跳过外循环宣称"已验收"。
3. 只有以下情况必须走外循环：部署到实例、采集验收证据、冻结交付物、验证只读/打包/迁移相关行为。
4. 内循环发现的问题同样要留回归测试（先失败后通过），不能只在 dev 里"看着好了"。

## 3. 宿主 vs 容器分工

**宿主原生允许**：dev server（`bun run dev` / `bun run dev:spa`）、`bun run check <files>`、宿主 vitest 单测、只读诊断查询（`docker exec` 只读 SQL、日志读取）。

**仍必须在容器**：真实 PostgreSQL/Keycloak/Redis 等服务、发布构建、迁移重放、浏览器驱动、任何需要固定工具链/资源限额/隔离性的证据采集。

不变的硬规则：

- 不读取、不复用、不重启其他业务服务及其数据库；不驱逐业务缓存；
- 凭据不进 argv、日志、Git、公共证据；私有材料只留 `~/.config/youlin/mvp/`（0600/0700）；
- 宿主原生执行的结果在证据里标注 `runner=host`，与容器结果**分开计数、不混算**；
- 一次性诊断脚本保持简单、可删除，用完即删，不沉淀成永久基础设施。

## 4. 构建加速（实测基线 → 目标）

实测基线：单次构建 **601s** = 前端 5 段串行 338s（desktop 113 / mobile 95 / share 77 / workbench 36 / auth 17）+ 后端 Next **262s**。宿主 80 核但**可用内存仅 ~19 GiB**，内存才是约束。当前 `node_modules/.vite` 是 tmpfs、`next/cache`（968 MB）随 artifacts 丢弃 → **每次都是全冷构建**。

| 杠杆 | 做法 | 目标 | 护栏 |
| --- | --- | --- | --- |
| 阶段跳过 | 前端输入哈希未变则复用上次 `dist/` | **-338s** | 打印复用清单与哈希；`--full` 强制全量；发布构建禁用 |
| 前端并行 | 5 段独立，按可用内存并行 3 路 × 4 GiB | 338s → **~120s** | headroom 按并行总限额重算；不扩预算、不停业务服务 |
| 持久缓存 | Vite `.vite`、Next `.next/cache` 改宿主缓存目录，按 lockfile+配置哈希分命名空间 | 后端 262s → **~150s** | 缓存只加速不定义正确性；发布构建 `--no-cache` |
| 部署快路径 | 仅 app 改动时 `up -d --force-recreate app` | **-40~60s** | 涉及迁移/profile 变更仍走完整链 |
| 测试合并 | 相关文件一次 vitest 调用；多文件放开 workers | 每次 -10~30s | 保留互补分片语义，不删用例、不提限时 |

目标：仅服务端改动 **~150s**；前端改动热缓存 **~230s**；**发布/证据构建保持冷全量 601s**（可重复性基线不动）。

证据标注要求：加速构建必须记 `cache=warm|cold`、`parallel=N`、`skipped=[...]`，不得把加速构建当作冷构建的可重复性证明。

## 5. 执行口径（防虚报）

- 计数**不跨入口重复累计**；身份套件两片必须同一版本一起看，单片不算全量。
- 负向/回归用例必须**先失败后通过**，否则不算回归证据。
- 超时、被杀、OOM 的运行**不得记为通过**；不提高单次限时、不删用例、不排除业务代码来刷绿。
- 全仓类型门与远端 CI 未通过时，不得声称"质量门通过"；只说定向检查通过及其范围。
- 真实验证必须走**产品入口**（真实登录、真实接口）；直连数据库伪造会话不算。工程播种（如 `psql` 直写授权行）必须标注为**工程验证**，不是产品流程，也不得当作 S4 管理界面已交付。
- 构建成功 ≠ 功能可用；登录成功 ≠ 授权/额度/隔离已验收。

## 6. 资源与磁盘治理

- 内存 headroom 按**并行度**重算；可用内存不足时降并行或排队，不扩预算、不停业务服务。
- 构建 artifacts 只保留最近 2 个（本轮清理释放 30 GB，磁盘从 86% 降到 83%）；缓存目录设配额与 LRU。
- 构建前检查剩余磁盘；磁盘不足时先清理再构建，不允许构建到一半失败留下半成品。
- 一次性网络/路由修复（如宿主出网规则）必须有可重放脚本，并在文档写明"重启后需重放"。

## 7. 证据与台账

- 每轮冻结：`manifest.json`（源码哈希、镜像 sha256、检查项与计数、`runner`、`cache/parallel` 标注）+ 关键原始日志 + **失败证据不覆盖**。
- 私有材料（截图、env、凭据、原始浏览器事件）留 `~/.config/youlin/mvp/`，不入库、不上公共 Acceptance。
- 台账分工：[09 进度](./09-development-progress.md)、[11 决策](./11-m0-m2-confirmed-decisions.md)、[13 缺口](./13-m0-m2-delivery-gap-register.md)、`evidence/` 冻结证据；**不回写已冻结历史**，需要补充就新增记录。

## 9. 待决策

1. 并行度与内存预算：建议前端并行 3 路 × 4 GiB + 后端 6 GiB（峰值 12～14 GiB，可用 ~19 GiB）。
2. 发布/证据构建是否坚持冷全量（建议坚持，代价约 +7 min）。
3. `migrate` 是否允许"journal 未变则跳过重放"（建议不跳过，只优化 app-only 部署）。
4. 云上托管：Redis 可直接换阿里云 Tair；PostgreSQL 受 **`pg_search`（ParadeDB，14 个 BM25 索引）** 阻塞，RDS 通常不提供，需在"ECS 自建 ParadeDB / 检索改道 Elasticsearch / 混合"三条路径中先做兼容性验证。
