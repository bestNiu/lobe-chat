## 3. 跨里程碑公共门禁

### 3.1 身份和权限门禁

所有新增页面、API、搜索索引、异步任务和 Agent 能力必须回答：

- 主体是用户、服务、Agent 还是外部 Client？
- Workspace/Project/资源范围是什么？
- 动作、Purpose、Audience 和有效期是什么？
- PDP 决定和 PEP 执行在哪里？
- 拒绝是否泄漏名称、计数、关系或元数据？
- 权限变化如何使 Session、缓存、索引和短期 URL 失效？

必须包含正向、负向、水平越权、跨项目和过期授权测试。

### 3.2 数据和隐私门禁

- 数据 Owner、分类、用途、来源、地域和保留明确；
- MVP 数据不包含受试者、人遗、PV、跨境和 GxP 受控记录；
- 日志、Trace、Prompt、错误和测试数据同样执行分类；
- 外部模型、Dify、RAGFlow、Tool 和供应商只接收白名单字段；
- 导出、下载和分享有接收方、用途、期限和审计。

### 3.3 API 和事件门禁

- OpenAPI/JSON Schema 和版本；
- 认证、Audience、Scope、配额和错误码；
- 写操作幂等、Expected Version 和业务回执；
- 事件有稳定 ID、来源、Schema、顺序/去重和重试；
- 契约测试、兼容策略和弃用窗口；
- 不暴露内部数据库表、对象 Key 和供应商私有 Schema。

### 3.4 UI/UX 门禁

- Loading、Empty、No Permission、Error、Timeout、Degraded、Session Expired；
- 键盘/基础无障碍和企业浏览器支持；
- 高风险动作显示目标、影响、数据和确认；
- 错误页面显示用户可理解信息和 Trace ID；
- Desktop/Web 一致性和响应式范围；
- 用户测试证明入口可发现、任务可完成。

### 3.5 可观测和运行门禁

- Health/Ready；
- 结构化日志且无不必要敏感正文；
- Request/Trace/Run/Job ID；
- 成功率、错误率、延迟、队列、配额和成本指标；
- 告警 Owner、阈值、升级和 Runbook；
- 失败可重试/补偿/人工处理；
- 发布、回滚、备份和恢复步骤已验证。

## 4. 里程碑 Review 会议模板

每个里程碑关闭前必须回答：

1. 目标用户能完成什么真实任务？
2. 哪些功能已完成，哪些通过 Feature Flag 关闭？
3. 哪些 AC 和非功能门槛通过？
4. 权限负向测试是否覆盖所有新入口？
5. 数据、Secret、日志和审计是否符合边界？
6. 性能、容量、故障和恢复证据是什么？
7. 还有哪些 P0/P1 缺陷和未接受风险？
8. 上游同步和后续迁移有什么影响？
9. Runbook、Owner 和支持机制是否就绪？
10. 是否允许下一个里程碑依赖该能力？

结论只能是：

```text
accepted
accepted_with_conditions
rejected
```

`accepted_with_conditions` 必须有风险 Owner、补偿控制、修复日期和到期复审。

## 6. 缺陷和风险退出标准

| 严重度 | 示例 | 里程碑处理 |
| --- | --- | --- |
| Critical | 跨租户/项目泄漏、生产 Secret 暴露、不可恢复数据损坏 | 必须修复并复测 |
| High | 权限旁路、高风险 Tool 绕过、错误业务终态、备份不可恢复 | 必须修复或正式 No-Go |
| Medium | 有受控替代路径的核心体验/稳定性问题 | Owner 接受、明确版本修复 |
| Low | 非关键体验和优化 | Backlog |

- 身份和权限负向测试；
- SAST/SCA/SBOM/镜像和 Desktop 签名；
- API/事件/Schema 契约测试；
- RAG/Agent/Workflow 评测；
- 性能容量和故障注入；
- OSS/索引/湖仓一致性；
- 备份、恢复、升级和回滚；
- UAT、培训和 Go/No-Go；
- 已知问题、风险接受和支持 Runbook。
