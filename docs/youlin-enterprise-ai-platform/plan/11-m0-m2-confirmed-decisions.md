## 本次更正（覆盖旧假设，不改写历史证据）

用户明确更正：CI 使用 **GitHub Actions**，不是 GitLab；UAT 在**本机 Docker 部署环境**中验证，不再等待其他机器。完整环境向其他目标机器的部署后续推进，本阶段先整理完整部署文档。旧提交及冻结证据中 GitLab/外部 UAT 的文字只代表当时假设，不再是执行依据。

用户后续允许依据本机实测可用资源设定部署预算，但必须给既有业务服务留余量、逐服务限额；不读取或复用已有业务数据库，不无界占满内存/Swap，也不因此开放生产数据。现有工程测试不自动升级成 UAT。UAT 必须实际启动当前版本应用及必要依赖，执行用户流程并保存证据。

## M0～M2 的完成定义不缩水

- **M0**：范围、架构决策、责任、风险与待办有版本记录；已确认/候选/未确认分开。预算、保留、供应商事实等未知项不得伪填。
- **M1**：可重复容器部署、依赖/制品、质量门、私有 CI 材料、Secret/可观测/Flag/队列/审计骨架和清理回退分别有实证；某个工具通过不等于12项全部完成。
- **M2**：Keycloak 客户端/认证、应用账号映射、绑定冲突、撤权、服务身份和双端协议分别落实；密码登录通道与企业微信通道解耦。真实 HR、企业微信、签名和本机 Docker UAT 缺证据时保持待验收；不能把环境位置已确定写成验收完成。

## 安全默认值与非确认项

- 不仅凭员工号格式、邮箱或名称把两个人合并；员工号唯一/不复用已确认，但HR稳定人员主键映射与并行任职事实仍需核验。
- SMTP真实配置已保存在本机私有文件；保存配置不等于验证邮件或密码重置投递成功。合成账号的已核验邮箱只用于隔离夹具。
- 未配置持久权威状态读取时不开放受保护操作。JWT 签名有效不是员工仍在职或仍有访问权的证明。
- 双人审批/紧急账号等要求职责分离的能力保持关闭，直到有第二位独立授权人。
- 保留期限、RPO/RTO、实际容量、GitHub Runner/镜像仓库配置与正式域名仍待输入；不因此退回宿主测试或开放生产访问。
