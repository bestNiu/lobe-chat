## 3. 状态、数据与一致性

UATScenario{role,task,scope,preconditions,expectedOutcome,acRefs}；UATRecord{build,participantRef,observedSteps,result,defects,signer,conditions}；参与者不与自动测试结果混计。

以上为验证/发布/运营证据记录候选，优先使用现有受控证据库/测试管理系统，不要求新增业务数据库。记录须有明确字段、版本、访问范围、保留与完整性；涉及真实人员仅存受控引用，不在Git保存名单/敏感原文。

## 4. 接口、事件与交互

### 4.1 操作候选

准备角色/数据→执行登录问答/资源/记忆/共享/数据申请/任务/反馈/运营→观察结果与权限→访谈→逐AC汇总；记录失败/未测而非诱导打勾。

本项主要是测试、发布或运营流程，不新增业务API；被测接口使用已批准合同。须补可执行脚本/检查表/样本/停止与清理步骤、环境权限和受控证据格式。没有新增接口/迁移/页面的项可注明N/A并说明理由，不能用N/A免除真实验证。

### 4.2 产品状态

验收表显示任务可完成性、边界理解、可访问性和阻断，签署明确制品/日期/范围；截图脱敏。

前后端共同验证 loading/empty/forbidden/error/expired/degraded/conflict；不适用状态需写原因。高风险确认必须说明影响，不能拿弹窗替代授权。

## 5. 授权、失败与安全

业务接受不能豁免Critical/High或开放P0/P1缺陷；跨项目角色用合成/批准数据；受试者/GxP场景仍排除。

统一错误信封 `{requestId,error:{code,message,retryable,details}}`；未认证 401、不可发现对象 404、版本/幂等冲突 409、输入不合法 422、限流 429；依赖失败与结果未知分开。重试资格取决于幂等/回执，不能仅因 HTTP 5xx 重放副作用。
