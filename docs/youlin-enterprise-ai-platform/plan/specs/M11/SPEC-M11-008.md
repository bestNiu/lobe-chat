## 1. 目标、故事与范围

作为用户和支持人员，我要把回答/引用/系统问题分类、指派、处理并收到结果，而不默认把全部会话交给支持。

逐项 FR：FR-K04、FR-H03；AC 分项：AC-31、AC-21。本项提供分项证据，不独立代表整个 AC 签收；主责见[追踪矩阵](../../02-traceability-and-delivery-gates.md)。

不纳入：未批准临床/受试者/人遗/PV/GxP 数据、外部生产开放、任意插件热装、生产高权限 Pi 执行、全量历史迁移。功能基线不因本设计扩大。

## 3. 状态、数据与一致性

Feedback{id,submitter,category,runRef,citationRef,requestId,consentedExcerptRef,classification,status,assignee,version,resolution}；最小反馈事件沿用M8 ID，支持附件另行扫描/授权。

所有字段为逻辑候选，尚非 Drizzle/迁移交付。必须补类型/可空/索引/复合 FK、唯一约束、版本与保留。Workspace/Project 引用不信任客户端；版本不可静默覆盖；生命周期按 D13，不臆造法定年限。

## 4. 接口、事件与交互

### 4.1 操作候选

submit/triage/assign/requestClarification/resolve/reopen/notifyResult；只引用获权问题对象，用户显式选取可提交片段；状态new/triaged/inProgress/waiting/resolved/closed候选，决定与通知回执分开。

跨系统 OpenAPI/JSON Schema、内部运行时校验仍须下一步展开；操作名不是已上线 URL。变更用 expectedVersion/幂等键，事件用 K03 CloudEvents；Request ID/traceparent 贯穿但不授予访问权。

### 4.2 产品状态

用户可见自己的进度/结果，支持者可见授权摘要；源已撤回显示受限，不缓存过期全文；关闭有解决说明，可重开。

前后端共同验证 loading/empty/forbidden/error/expired/degraded/conflict；不适用状态需写原因。高风险确认必须说明影响，不能拿弹窗替代授权。

## 5. 授权、失败与安全

Trace ID不授原文读取；支持者按工单目的/范围获得最小材料，不继承用户所有对话；敏感附件脱敏/隔离；客户或其他项目工单不可枚举。

统一错误信封 `{requestId,error:{code,message,retryable,details}}`；未认证 401、不可发现对象 404、版本/幂等冲突 409、输入不合法 422、限流 429；依赖失败与结果未知分开。重试资格取决于幂等/回执，不能仅因 HTTP 5xx 重放副作用。

## 7. 发布、迁移、运行与回退

W16已有最小反馈采集/人工处理，W22统一工单运营与SLA；保留/附件删除/受控证据按D13，结果通知遵守当前权限。

新 Schema 用 expand/migrate/contract，存量能力默认未批准；无法安全降级时前向修复。可观测含成功/失败/延迟/未知/撤权/预算/版本，不包含不必要原文。回退不得恢复已撤销访问或删除数据。
