## 1. 目标、故事与范围

作为能力 Owner，我要用统一版本注册 Agent/Skill/Tool/Workflow/Prompt 和插件包，避免目录页面各自维护一份定义。

逐项 FR：FR-D01、FR-D02、FR-E01、FR-F01、FR-H01；AC 分项：AC-06、AC-07、AC-08。本项提供分项证据，不独立代表整个 AC 签收；主责见[追踪矩阵](../../02-traceability-and-delivery-gates.md)。

不纳入：未批准临床/受试者/人遗/PV/GxP 数据、外部生产开放、任意插件热装、生产高权限 Pi 执行、全量历史迁移。功能基线不因本设计扩大。

## 3. 状态、数据与一致性

Capability{id,kind,workspaceId,owner,status}；CapabilityVersion{id,capabilityId,version,manifestHash,dependencyRefs,schemaVersion,risk,scope,createdBy}；unique(capabilityId,version)。PluginPackage/Version 与 Installation/Binding 分开，Secret 仅引用。

所有字段为逻辑候选，尚非 Drizzle/迁移交付。必须补类型/可空/索引/复合 FK、唯一约束、版本与保留。Workspace/Project 引用不信任客户端；版本不可静默覆盖；生命周期按 D13，不臆造法定年限。

## 4. 接口、事件与交互

### 4.1 操作候选

list/get/createDraft/createVersion/resolvePublished；目录发现也授权；修改草稿版本递增，published 内容不可覆盖。依赖指向精确版本或批准锁定快照，装载前检查存在/兼容/停用/依赖环。

跨系统 OpenAPI/JSON Schema、内部运行时校验仍须下一步展开；操作名不是已上线 URL。变更用 expectedVersion/幂等键，事件用 K03 CloudEvents；Request ID/traceparent 贯穿但不授予访问权。

### 4.2 产品状态

各中心共享列表/详情/版本/Owner/风险/用途/授权状态，不要求多个微服务；用户只见可用目录，Creator 只管授权草稿。

前后端共同验证 loading/empty/forbidden/error/expired/degraded/conflict；不适用状态需写原因。高风险确认必须说明影响，不能拿弹窗替代授权。

## 5. 授权、失败与安全

稳定 ID 不等于可读；Plugin 发布≠安装≠启用≠有权调用；同名工具不可静默替换；不从公共市场运行时拉取最新包。

统一错误信封 `{requestId,error:{code,message,retryable,details}}`；未认证 401、不可发现对象 404、版本/幂等冲突 409、输入不合法 422、限流 429；依赖失败与结果未知分开。重试资格取决于幂等/回执，不能仅因 HTTP 5xx 重放副作用。

## 7. 发布、迁移、运行与回退

新增 registry 表及复合范围约束，旧能力按未审核草稿迁入；候选 enterprise.capabilities Flag 仅控入口，服务端仍强制；与 K04 合同映射。

新 Schema 用 expand/migrate/contract，存量能力默认未批准；无法安全降级时前向修复。可观测含成功/失败/延迟/未知/撤权/预算/版本，不包含不必要原文。回退不得恢复已撤销访问或删除数据。
